# GitHub 开源发布与社区运营

本项目负责 `OpenCompare` 在 GitHub 上的日常盯盘、发布前实测验收、每日定时发版以及 Issue 回帖收口。

## 值班任务与分工

1. **`github-issue-pr-actions.md`（每 5 分钟）**：先由 `guards/github-sentinel.mjs` 零 Token 检查是否有未读的 Issue、PR 评论、CI 构建失败或严重安全告警；有新动静才唤醒 Agent 做一线分诊与回执，不直接改产品源码。
2. **`release-batch.md`（每日 07:00）**：检查主分支是否有尚未发布的新提交；若有则触发发版预检与 Release 流程，无新提交则安静收工。
3. **`l1-package-smoke.md`（按需触发）**：从 GitHub Releases 公开链接下载正式安装包，验证 SHA-256、签名公证与冷启动冒烟。
4. **`l2-large-dir-load.md`（条件触发）**：当代码改动涉及目录扫描、哈希或渲染性能时，运行大目录对比与多会话内存稳定性测试。
5. **`l3-cdp-ui.md`（条件触发）**：当改动涉及界面交互时，驱动真实桌面窗口验证双目录对比、下钻、三向合并与 HTML 报告导出。
6. **`l3-computer-native.md`（条件触发）**：当改动涉及操作系统原生文件选择器、单实例唤醒或系统菜单时，在真实桌面环境中执行系统窗口测试。
7. **`issue-closeout.md`（发版后触发）**：新版本安装包验证通过后，带着版本号与验证结论去对应 GitHub Issue 下礼貌回帖并关闭工单。

## 运行边界

- 所有日常任务对代码仓库保持**只读**，不直接在主分支手改或提交代码；确认需要修改源码的缺陷，一律交接给独立分支的研发工作项处理。
- `guards/state/` 用于记录已处理的事件游标，`shipped/` 为宿主运行记录，请勿手动删改。
