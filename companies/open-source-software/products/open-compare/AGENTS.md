# OpenCompare 产品约定（AGENTS.md）

## 一、产品定位
`OpenCompare` 是对标 Beyond Compare 5 Pro 的现代跨平台文件 / 目录树 / CSV 主键表格 / JSON 语义对比与三向冲突合并桌面工具。核心目标是提供零外部 API 依赖、高速确定性、现代 UI 体验的桌面对比与合并成品。

## 二、核心功能边界与优先级约定

### 1. P0 必交核心（最高优先级，确定性验收闭环）
1. **双目录树只读高速对比**：
   - 支持左右双目录树按文件大小、修改时间、内容哈希（SHA-256 / 快速哈希）高速增量比对；
   - 支持一键过滤展示：`全部 (All)`、`仅差异 (Diffs Only)`、`仅左侧独有 (Left Only)`、`仅右侧独有 (Right Only)`、`仅相同 (Identical)`；
   - 支持从目录树双击任意差异文本/代码/CSV/JSON 文件，直接下钻打开对应的文件级对比视图。
2. **代码/文本双栏 Diff 与三向冲突块点选合并（3-way Merge）**：
   - 双栏文本 Diff：支持同步滚动、行级增删改着色与行内字符级（inline char-level）高亮 Diff；
   - 三向合并（3-way Merge）：支持 `base / ours / theirs` 冲突块可视化定位、冲突块计数与上下跳转、逐块一键点选采纳（`Accept Ours` / `Accept Theirs` / `Accept Both`）及实时预览并导出合并结果。
3. **千行 CSV 按指定主键列对齐对比（核心亮点）**：
   - 支持千行级标准 CSV / TSV 导入，指定单列或多列作为主键列（Key Column）自动行对齐（容忍乱序行）；
   - 支持列偏移容错与表头映射，精准识别并分类统计`新增行`、`删除行`、`修改行`，并对修改行内的单元格级数值变动做高亮标记。

### 2. P1 增强体验（不阻塞 P0 主线验收）
4. **JSON / YAML 结构化语义对比**：
   - 解析 AST / 对象树，自动忽略键序打乱与缩进格式噪音，按节点路径展示真实的键值新增、删除、修改与类型变更。
5. **社区高价值确定性能力**：
   - **文件夹单向镜像/增量复制同步（预览确认制）**：在 P0 双目录对比基础上，提供带 Dry-run 变更清单确认弹窗的「左→右 / 右→左 增量复制同步（仅覆盖差异与补齐缺失，默认不勾选高危删除或需二次确认）」。
   - **跨层级散乱目录树按模板归位/提取器**：以源目录树 `a` 为结构模板，通过文件名 + 内容哈希从层级被打乱的目录树 `b` 中秒级匹配文件，并按 `a` 的相对路径结构预览/提取归位到目标输出目录。
   - **diff 行级差异指示条（diff gutter indicator）**：在双栏 diff 侧边绘制窄竖向指示条，将已算出的行级四态按位置聚合标出差异位置，随滚动同步、支持点选跳转；**只做四态聚合绘制，不做文本渲染缩略图**，不改变窗口化渲染与大目录性能口径。
   - **交互与主题体验增强**：未知扩展名按文本探测打开；亮/暗主题与跟随系统主题成套切换（diff 语义色 token 同步切换）；重新加载当前 diff、忽略空白字符差异、交换左右面板、文件对话框记住上次目录。

### 3. 明确不做（红线边界）
- 不做「局域网二维码静态 Diff 报告（手机扫码看报告）」；
- 不做十六进制/二进制反汇编对比；
- 不做 `.xlsx` 复杂合并单元格与公式解析；
- 不做重型富文本 IDE 自由代码编辑器；
- 暂不排期 FTP / SFTP 远端对比，不预留远端抽象层。

## 三、技术选型与架构约定
- **独立技术调研先行**：在拆解大功能前，先调研选定对 AI Agent 编码最友好、构建闭环最快、性能与桌面视觉体验达标的技术栈与开源组件。
- **内置标准测试样本库（Sample Fixtures）降级为辅助入口**：内置样本仅用于快速演示与自动化回归，必须以显式标注的「加载演示样本」辅助入口提供、且可被用户跳过；**不得占据首屏主工作流，也不作为任何验收/达标的判定口径**——达标一律以真实文件端到端读写为准。保留的样本内容：
  1. 双目录树对比样本（含多层嵌套、修改文件、左右独有文件及被打乱层级的待归位样本目录）；
  2. 代码双栏 Diff 样本与含多处标准冲突块的 `base / ours / theirs` 三向合并样本；
  3. 千行级乱序主键、含新增/删除行与单元格数值微调的对账 CSV 样本；
  4. 键序打乱且含深层键值变更的 JSON / YAML 配置对比样本。

## 四、桌面实机验收核心路径（真实文件端到端读写，全程零样本依赖）

- 交付含界面可见变更时，发版前须通过桌面实机验收（纯文档或纯后台改动免跑）：
  - **软件界面交互实测（`l3-cdp-ui`）**：用 `--remote-debugging-port` 驱动真实窗口的渲染层，覆盖对比工作台、目录对比下钻、新建对比粘贴路径、多会话切换与关闭等界面路径。
  - **桌面系统窗口实测（`l3-computer-native`）**：针对原生 `NSSavePanel` 导出/保存、系统文件选择器、打包态命令行参数与 `opencompare://` 单实例接管、应用图标/关于面板/原生菜单，在真实桌面环境中测试。
- 实机验收单场控制在 30 分钟以内：开工即建立 `digest.md` 骨架，每验完一条立即追加结论与证据路径。

**五条核心必验路径：**
1. 启动应用，验证冷启动即进入可直接使用的对比工作台（内置 Sample 降级为可跳过的辅助入口，不占首屏主工作流）。
2. 真实文件/目录打开与拖拽：经系统文件选择器打开真实文件/目录，并支持拖入真实路径与真实体量，接受真实输入而非预置样本。
3. 目录对比下钻与返回：真实目录对比结果双击差异项可下钻到文件级对比视图，并能逐级返回上级目录视图，往返不丢状态。
4. 多会话标签管理：可同时打开多个对比会话并在标签间切换、关闭，未保存状态有明确提示，无只能靠刷新/重启脱困的交互断头路。
5. 原位保存与结果导出：真实修改可原位保存回磁盘，合并/对比结果可导出为可复现的文件产物（非仅停留在界面态）。

- **目录对比 HTML 报告导出的验收五条**（缺一条不算交付）：
  1. **转义与注入**：文件名 / 路径一律 HTML 转义；用例必须含 `<script>`、`&`、引号、换行、emoji、超长文件名；报告不得因文件名破版或执行任何标记。
  2. **隐私默认**：左右路径默认相对化到公共祖先，并提供默认开启的「隐藏本机路径」开关；报告顶部固定一行「由本机生成，分享前自查路径」。
  3. **上限写死可复核**：行数 ≤200,000 行、字节 ≤10 MB 写死在实现常量并写进报告元信息；截断时报告内写「已展示 N / 原始 M（已截断）」并说明子树不全；单测覆盖刚好上限、超一行、超十倍三种。
  4. **自包含可离线**：产物内 `<script`、外链 CSS / 字体 / 图片、`http(s)://` 资源引用、`fetch` 各 0 命中；`file://` 直接打开可读；这几项进断言。
  5. **与界面同源**：四态计数与版本取自同一状态源，不在导出时重算；导出后逐项与界面数字对比；报告 `<html lang>` 跟随当前界面语言。

## 五、仓库工程结构与复用约定

- 域目录 `src/domains/`：`compare-request`（手工输入 / argv / URL 的统一解析与校验契约）、`release`（图标资产、打包一致性、发版文档）、`desktop-shell`（窗口、dock、关于面板、原生菜单）。菜单 / 快捷键 / 关于面板的后续扩展落 `desktop-shell`，不要塞回 `release`。
- 手工入口、启动参数、`opencompare://` 三个入口必须复用 `parseCompareUrl` / `parseCompareArgv` / `parseManualPaths` / `resolveCompareRequest` 与 `CompareErrorCode`，禁止另写一套解析；扩展名白名单只在 `src/shared/fileExtensions.ts` 维护。
- 路径上下文的唯一来源是 `PlatformPort`：`statPath` 探测 + `homeDirectory()` / `workingDirectory()`（Web 端返回 `/memory`），`~` 与相对路径展开只在这里取上下文，renderer 不得自行猜测。
- `openFilePair` / `runSidesCompare` 返回 `boolean` 并接受 `onError`：新入口（对话框、启动参数、URL、拖拽）失败必须就地提示且不建 tab、不替换现有会话，禁止退回「吞错误 + workbench notice」。
- 品牌图标源为 `build/icons/icon.svg`，生成的多尺寸 PNG / icns / ico 必须入库（二进制不忽略）；`build/*.mjs` 生成脚本沿用 `eslint.config.mjs` 的 node globals override。
- 发布约定：版本号唯一来源是 `package.json#version`，发布门测试与 `release.yml` 断言从它推导（内联版本字面量不再新增）；已公开的 tag 永不重写、强推或删除，发版失败就新建补丁版本。
- README 保持 9 节精简双语结构：`README.md` 英文默认、`README.zh-CN.md` 中文镜像，两版第 3 行互链、H2 一一对应、英文正文 ≤700 词。第 5 行只保留一行「最新公开版本 → Releases 页」，**指向已发布版本，不随 `package.json#version` bump 变动**；发布完成后同步更新两版这一行与 `release-packaging.test.ts` 的 `latestPublishedTag` 锚点。

## 六、对外承诺与日常值班配置

- 哨兵预检脚本（`guards/*.mjs`）只按「`state/seen.txt` 里未见过的 issue / PR / 失败 run 集合」判定唤醒：窗口滚动、已被同分支更晚绿色 run 取代的失败、同一 run 的分支标签变化都不算新事件；游标由当班按 guard 实跑 marker 回写，收工前复跑必须 `exit=1`。
- guard 退出码口径：`exit=0` = 有新事件、唤醒 Agent；`exit=1` = 无新事件、不唤醒；`exit=2` = guard 自身出错。已回执但尚未关单的条目指纹必须原样留在 `seen.txt`，**禁止从游标里删掉未完成指纹**。
- **对外回帖身份固定为 `munk-agent`**：GitHub 回帖 / 打标签 / 关单一律走 `node guards/gh.mjs`（读取 `[github].munk_agent_token`），**禁止用本机个人 `gh` 登录代发**。回帖后必须复核作者 `author.login === munk-agent`。
- **日常运营固定 7 条值班任务**：
  1. `github-issue-pr-actions`（GitHub Issue 与构建报错盯盘，每 5 分钟定时预检）
  2. `release-batch`（每日 07:00 定时发版）
  3. `l1-package-smoke`（安装包下载与启动自检，按需触发）
  4. `l2-large-dir-load`（大文件夹加载性能测试，按改动触发）
  5. `l3-cdp-ui`（软件界面交互实测，按改动触发）
  6. `l3-computer-native`（桌面系统窗口实测，按改动触发）
  7. `issue-closeout`（新版本发布后自动回帖关单，发版后触发）

## 七、大目录性能与虚拟滚动架构约定

- 目录内容哈希只在主进程 / 平台层完成：用 `node:crypto` 流式读文件字节算 `sha256`，不经 UTF-8 字符串往返；renderer 不得为比对逐文件拉取全文。Web 端保留同构回退实现，两实现对同一文件必须给出相同摘要，含非法 UTF-8 字节的二进制样本不得被判 same。
- 目录条目读取走批量 / 分页 IPC，遍历与哈希的并发必须有界且可配置；单个坏项（悬空链接、不可读）只跳过并计数，不得让整棵树失败。
- 摘要（`digestFiles`）同样必须分块：一次 IPC 只覆盖一个有上限的批次（`DEFAULT_DIGEST_BATCH_SIZE`），禁止把全树候选路径与等长结果数组塞进单次结构化克隆往返。进度与取消只挂在分块结算点上，取消后不得提交半棵树或半份缓存。
- 目录对比结果树与其它可能承载 10 万+ 条目的列表必须按可视窗口渲染，禁止为全量条目建 DOM。
- 目录树行模型只在 `src/core/directory/rows.ts`（行持有节点引用、不复制节点与 children）；`collapsedPaths` 必须是稳定 `readonly string[]` 并作为 memo 键，禁止 Set 或每次渲染新建数组；五段过滤与左右投影按窗口按需计算，禁止 `filterDirectoryTree` / `projectDirectoryTree` 整树克隆。
- **双栏 diff 内容总高按「内部对齐行」计**：`DiffPane` 的行模型是对齐行（一侧更长的位置用 filler 行补齐），所以内容总高 = **对齐行数 × 20**，两栏严格相等。
- **切 tab 即时性是硬约束**：不得用「非活动 tab 只留摘要、激活时重建」换内存——非活动 tab 保留完整对比结果与行模型，切回不得触发重扫 / 摘要重算 / 空白态。
- **内存验收口径**：① 不崩（无 OOM / renderer 重启 / 未捕获异常）；② 3 tab 建齐后 +20 s 静置 ≤1300 MiB、app 总峰值 ≤2.5 GiB；③ 3 tab 驻留后同一实例连做 2 轮热 upsert，峰值与静置不逐轮抬升且 `hashedFiles=0`；④ 关掉一个 tab 后 renderer 回落 ≤1100 MiB；⑤ 瞬时峰值只作回归护栏 ≤2.25 GiB。
