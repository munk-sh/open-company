# 全网采集与情报深挖手艺（`web-recon`）

本技能定义矩阵内任何运营任务面对外部网页链接、社交媒体帖子或专项调研命题时的标准提取与核验规程。

> **角色边界提醒**：
> - **矩阵负责人（`company-owner`）** 不直接调用 `browse` 子专员。当人类给出链接或调研指令时，负责人应把指令写入对应频道 `radar` 的明确对象，或通过 `POST /tasks/:taskId/runs`（携带 `brief`）点名启动该频道的雷达任务。
> - **运营任务主会话** 加载本技能后，按以下分级通道采集一手信息。

## 一、三级网页与社媒提取路由（先轻后重，拒绝盲爬）

面对任何外部 URL 或待查信源，严格按以下优先级选择工具，禁止自己编写脆弱的临时爬虫脚本：

### 1. 第一级：公开静态网页 / 博客 / 文档 / 代码托管 $\rightarrow$ 直接调内置 `webfetch`
- **适用对象**：独立博客、Substack、技术文档、新闻资讯页、GitHub README / Issue / Discussion、Hacker News 讨论串、公开 RSS/Atom。
- **操作方式**：直接调用原生 `webfetch` 工具获取干净的 Markdown 文本。
- **升级判据**：若 `webfetch` 返回 `403 Forbidden`、Cloudflare 拦截页、空白 JS 骨架（正文少于 100 字），或目标天然属于需要登录/JS 渲染的平台，立即切入第二级。

### 2. 第二级：社媒平台 / 动态渲染页 / 评论区深扒 $\rightarrow$ 派发 `browse` 子专员
- **适用对象**：
  - **微信公众号文章**（`mp.weixin.qq.com`）
  - **小红书笔记与搜索结果**（`xiaohongshu.com`）
  - **X / Twitter 长推与评论区**（`x.com` / `twitter.com`）
  - **知乎回答、Reddit 讨论串、飞书公开文档、YouTube 页面字幕/高赞评论**
- **操作方式**：
  1. 主任务向 `browse` 子专员派发明确采集指令（一次派发聚焦一个明确目标或平台批次，避免并发争抢浏览器焦点）。
  2. 指令中必须要求 `browse` 子专员带回**一手原文摘录**：
     - 标题、作者/账号名、发布时间、原始 URL；
     - 核心正文段落（保留原始数据、定价、步骤与关键结论，禁止只返回笼统的一句话总结）；
     - 评论区前 5～10 条最高赞或最具代表性的**真实痛点/反驳/求教程原话**。

### 3. 第三级：登录墙与验证码处理（Human Assist 闭环）
- **严禁硬撞或索要密码**：当 `browse` 子专员回报目标站点弹出登录框、扫码墙或人机验证（Captcha）时，**严禁**多次刷新重试，**严禁**在对话或简报中要求人类输入账号密码。
- **标准动作**：
  - 若由父任务直接遇到阻塞，调用 `munk_request_human`（或在 `digest.md` 中置 `needsOwner: true`），清晰写明：「需要在浏览器中完成 `{平台名称}` 登录/验证，完成后即可复用登录态继续采集」，随后立即停手等待。

## 二、专项调研（Deep Recon）三步交叉核验法

当执行命题式调研（如「调研某赛道竞品」「深扒某产品差评与变现模式」）时，必须遵循以下三步法，杜绝把二手营销软文当事实：

1. **找一手源头（Primary Source First）**：
   - 谈产品/工具：必看官网定价页（Pricing）、官方文档、Release 或商店版本记录；
   - 谈行业数据/政策：必溯源到原始报告、论文或官方公告，不采信自媒体转述的无出处数字。
2. **扒真实体感（User Pain & Word-of-Mouth）**：
   - 去 X、小红书、Reddit、GitHub Issues 搜索『`{产品/关键词} 吐槽 / 踩坑 / 替代 / 贵 / 难用 / alternatives / pricing`』；
   - 摘录至少 3 条真实用户的具体抱怨原话（这往往是选题与套利切口的黄金矿脉）。
3. **跨网对比（Cross-Market Arbitrage）**：
   - 对比同一件事在英文圈（X / HN / Reddit）与中文圈（小红书 / 公众号）的认知温差：
     - 外网已经跑通变现、内网还没人讲透 $\rightarrow$ 标记为 **`[跨网信息差·内容机会]`**；
     - 外网工具太贵或水土不服、内网评论区都在求平替/代搭 $\rightarrow$ 标记为 **`[跨网信息差·搞钱机会]`**。

## 三、采集产物交付底线

无论输出到哪个频道的 `radar` 还是 `growth`，所有采集到的外部信息必须保留：
1. **可溯源 URL**（每一条核心事实或引述必须附带原始链接）；
2. **硬核细节**（具体数字、价格区间、转化率、时间节点、原话引述）；
3. **明确的「So What」判断**（这件事对该频道的内容选题、受众或转化意味着什么）。
